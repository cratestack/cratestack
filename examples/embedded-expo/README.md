# embedded-expo

CrateStack's embedded shape on React Native, via [Expo](https://expo.dev) and a local native module that wraps a Rust cdylib. Same `include_embedded_schema!` + `ModelDelegate` + JSON FFI envelope as every other embedded example — what changes is the host: instead of wasm in a browser or `flutter_rust_bridge` bindings, the React Native side talks to the cdylib through `expo-modules-core`.

## Layout

```
embedded-expo/
├── README.md
├── native/                              # Rust cdylib (workspace member)
│   ├── Cargo.toml                       # crate-type cdylib + rlib + staticlib
│   ├── notes.cstack
│   └── src/lib.rs                       # cratestack_init / cratestack_dispatch / cratestack_free
└── app/                                 # Expo TypeScript app
    ├── package.json                     # no dependency entry for cratestack-notes — it's a plain relative import, not a package
    ├── app.json
    ├── tsconfig.json
    ├── App.tsx                          # the UI — list / add / mark done / delete; imports from './modules/cratestack-notes'
    ├── (ios/ + android/                 # GENERATED by `npx expo prebuild`, gitignored — the *app's* platform
    │                                    #  projects, not the module's; see Bootstrap step 2 below)
    └── modules/cratestack-notes/        # local Expo native module (nested inside app/, no package.json/tsconfig.json of its own)
        ├── index.ts                     # typed accessors over the JSON envelope
        ├── android/…/CratestackNotesModule.kt   # CHECKED IN — hand-completed FFI bridge (Kotlin)
        └── ios/CratestackNotesModule.swift       # CHECKED IN — hand-completed FFI bridge (Swift), + CratestackNotes.podspec
```

The Rust dispatcher in `native/src/lib.rs` is testable in isolation (`cargo test -p embedded-expo-native`). The Expo side is hand-written TypeScript. The module's Swift/Kotlin/podspec/`build.gradle` under `app/modules/cratestack-notes/{ios,android}/` were originally scaffolded by `npx create-expo-module` and then **hand-completed** with the FFI bridge (see `native/src/lib.rs`'s C ABI) — they're **checked into git**, not regenerated on each checkout. Only the *app-level* `app/ios/` and `app/android/` directories (the Expo prebuild output for the app as a whole, distinct from the module) are generated and gitignored — see `app/.gitignore`.

## Prerequisites

- Rust + cargo. For real iOS/Android builds:
  - Android: `cargo-ndk` (`cargo install cargo-ndk`) + Android Studio + NDK
  - iOS / macOS: Xcode + Xcode CLI tools + an installed iOS Simulator runtime (Xcode → Settings → Components)
- Node.js 24+ and pnpm. (Node 20 reached end of life on 2026-04-30; the
  published `@cratestack/*` packages declare `engines.node >= 24`.)
- The Expo CLI tooling: `npx expo prebuild` / `npx expo run:ios` / `npx expo run:android` run your dev builds. (`npx create-expo-module@latest` is how the native module in `app/modules/cratestack-notes/` was originally scaffolded — see the Bootstrap section below — not something you run yourself.)

**Environment variables for Android.** Gradle's Android plugin needs `ANDROID_HOME` exported in the shell that runs `npx expo run:android`. If it's not set, you'll see `SDK location not found. Define a valid SDK location with an ANDROID_HOME environment variable...`. Easiest fix is in your `~/.zshrc`:

```bash
export ANDROID_HOME=$HOME/Library/Android/sdk
export PATH=$ANDROID_HOME/platform-tools:$ANDROID_HOME/emulator:$PATH
# Optional: pin Java for Gradle compatibility
# export JAVA_HOME=$HOME/.sdkman/candidates/java/21.0.2-graalce
```

Then `source ~/.zshrc` (or open a fresh terminal) before running the Expo commands below.

## Bootstrap (one-time per checkout)

**The local Expo native module (`app/modules/cratestack-notes/{ios,android}/…`) is already
scaffolded and hand-completed, and it's checked into git** — `CratestackNotesModule.swift`,
`CratestackNotesModule.kt`, `CratestackNotes.podspec`, and `build.gradle` already expose the two
Functions (`initDatabase(path: String)`, `dispatch(requestJson: String)`) that call into the Rust
C ABI (`cratestack_init`, `cratestack_dispatch`, `cratestack_free`). **Do not re-run
`npx create-expo-module` against this directory** — it would overwrite that hand-completed FFI
bridge with fresh scaffolding. (That command is how the module was originally created; it's
documented here for context, not as a step to repeat. If you ever need to recreate the module
from scratch, run it against a new/empty directory and diff the two native files back in by hand.)

```bash
cd examples/embedded-expo

# 1) Build the cdylib for each target you want to test on.
#    iOS Simulator on Apple Silicon:
cargo build -p embedded-expo-native --target aarch64-apple-ios-sim --release
#    iOS device:
cargo build -p embedded-expo-native --target aarch64-apple-ios --release
#    Android (cargo-ndk does all four arches in one go):
cargo ndk --target arm64-v8a --target armeabi-v7a --target x86 --target x86_64 \
    -o app/modules/cratestack-notes/android/src/main/jniLibs build --release -p embedded-expo-native

# 2) Install JS deps and run.
cd app
pnpm install
npx expo prebuild              # generates ios/ + android/ scaffolds for the *app*
npx expo run:ios               # or run:android
```

After this, regular development is `npx expo run:ios` / `npx expo run:android` from `app/`. Changes to `native/src/lib.rs` need a `cargo build` + a fresh `expo run`; changes to `app/modules/cratestack-notes/index.ts` or `app/App.tsx` hot-reload through Metro.

## How the wire protocol works

Same `OperationRequest` / `OperationResponse` JSON envelope used everywhere else cratestack does FFI:

```
JS:    { model: "Note", kind: "create", payload: { title, body, pinned } }
        |
        v   JSON.stringify → String → native.dispatch
        |
Native: cratestack_dispatch(bytes, len, &mut out_ptr, &mut out_len)
        |
        v   bytes back ← String back to JS
        |
JS:    { status: "ok", data: { id, title, body, pinned, completed, createdAt, updatedAt } }
```

The TS layer in `app/modules/cratestack-notes/index.ts` wraps this in typed functions: `listNotes()`, `createNote(input)`, `updateNote(id, patch)`, `deleteNote(id)`, `findNote(id)`. They all just construct the envelope, call the native bridge, and `JSON.parse` the response.

## Tests

```bash
cargo test -p embedded-expo-native        # dispatcher round-trips, error envelopes
```

Three tests:

- `create_then_find_unique_through_dispatcher` — full create → find_unique cycle through the JSON envelope.
- `unknown_model_returns_error_envelope` — request for a model that's not exposed returns `status: "err", code: "unknown_model"`.
- `dispatch_without_init_yields_not_initialized` — calling `dispatch` before `init_database` returns `status: "err", code: "not_initialized"`.

JS-level testing on the device happens once you run `npx expo run:ios` — there's no shortcut for that without the Expo runtime present.

### Android pipeline checkpoints

- `cargo-ndk` cross-compiles for all 4 ABIs (`arm64-v8a`, `armeabi-v7a`, `x86_64`, `x86`); `.so` files end up under `app/modules/cratestack-notes/android/src/main/jniLibs/<abi>/`.
- Gradle's `:cratestack-notes:mergeDebugNativeLibs` picks them up and packages them into the APK.
- Expo's autolinker discovers the local module (`cratestack-notes (0.7.10)` in the configure phase).
- `System.loadLibrary("embedded_expo_native")` resolves the JNI-mangled symbols (`Java_..._nativeInit`, `Java_..._nativeDispatch`); no `UnsatisfiedLinkError`.
- `cratestack-rusqlite` opens the SQLite file with WAL mode; rows visible via WAL journal until checkpoint, persist after process exit.
