# grpc-widgets-example

Smallest possible `transport grpc` CrateStack server — one `Widget` model, CRUD over real gRPC (HTTP/2, h2c plaintext) — plus three generated client integrations calling it live: Rust (native `tonic`), TypeScript (browser gRPC-Web), and Dart (native `package:grpc`).

## What it shows

- **`transport grpc`, end to end.** The schema (`schemas/widgets.cstack`) declares `transport grpc` instead of REST/RPC; `include_server_schema!` mounts a real tonic service (`ModelWidgetList/Get/Create/Update/Delete` on `widgets_api.Api`, plus the unary `ProcedureEchoWidgetName` and server-streaming `ProcedureWidgetNameSamples` procedures — ticket #208) via `cratestack_schema::grpc::into_router` — no external proxy, one deployable binary.
- **The `.proto` contract and field-number lockfile.** `schemas/widgets.pb.lock` (committed) pins every field's wire number; `schemas/widgets.proto` is the artifact `cratestack generate-proto` emits from it — the same numbers the Rust server, the Rust client, the TypeScript client, and the Dart client all agree on. See [`docs/design/protobuf.md`](../../docs/design/protobuf.md).
- **Three independently-generated clients, same schema, same server.** `rust-client/` talks real HTTP/2 gRPC via `tonic::client::Grpc`, generated by `include_client_schema!` (ticket #209) — no `tonic-build`/`protoc`, hand-rolled the same way the server's tonic service is (see `cratestack-macros::include::client::grpc`'s module doc). `ts-client/` talks gRPC-Web over `fetch` (browser-viable, no external proxy — an in-process `tonic-web` layer handles it). `dart-client/` talks real HTTP/2 gRPC via `package:grpc`. None of the three depends on `protoc`, `protoc-gen-grpc-web`, or `protoc-gen-dart` — every wire codec is hand-rolled by its respective CrateStack generator.
- **`grpcurl` works too**, since it's a real gRPC service — see the server's own `cargo run` output for the exact command.

## Run the server

```bash
export DATABASE_URL=postgres://cratestack:cratestack@localhost:55432/cratestack_test
cargo run -p grpc-widgets-example
```

(`compose.yml` at the repo root brings up that Postgres — `docker compose up -d postgres`.)

Verify with `grpcurl` (no client generation needed):

```bash
grpcurl -plaintext -import-path examples/grpc-widgets/schemas -proto widgets.proto \
  -H 'x-auth-id: 1' -d '{"name": "gizmo"}' \
  localhost:50061 widgets_api.Api/ModelWidgetCreate

# Ticket #208: unary procedure.
grpcurl -plaintext -import-path examples/grpc-widgets/schemas -proto widgets.proto \
  -H 'x-auth-id: 1' -d '{"name": "gizmo"}' \
  localhost:50061 widgets_api.Api/ProcedureEchoWidgetName

# Ticket #208: server-streaming procedure (List-arity return).
grpcurl -plaintext -import-path examples/grpc-widgets/schemas -proto widgets.proto \
  -H 'x-auth-id: 1' -d '{}' \
  localhost:50061 widgets_api.Api/ProcedureWidgetNameSamples
```

## Run the Rust client (native tonic gRPC)

```bash
cargo run -p grpc-widgets-rust-client-example
# or, the load-bearing integration test:
cargo test -p grpc-widgets-rust-client-example --test e2e -- --nocapture
```

Connects with a real `tonic::transport::Channel`, drives the client through create/get/update/list/delete, and asserts a typed `GrpcClientError::Status` carrying `tonic::Code::NotFound` on get-after-delete — same checks as the TS/Dart scripts, over the same binary gRPC framing the server and `grpcurl` already speak. See [`rust-client/src/main.rs`](rust-client/src/main.rs)'s module doc for the envelope-signing design note (`cratestack-client-rust::grpc::canonical`).

## Run the TypeScript client (gRPC-Web)

```bash
cd examples/grpc-widgets/ts-client && npm install && npm run build
node examples/grpc-widgets/ts-client-e2e.mjs
```

Drives the client through `fetch` against the running server: CORS trailer-header exposure, create/get/list/update/delete, and a typed `CratestackGrpcError` on get-after-delete. See [`ts-client/README.md`](ts-client/README.md) for the generated package's own API docs.

## Run the Dart client (native gRPC)

```bash
cd examples/grpc-widgets/dart-client && flutter pub get
dart run tool/e2e.dart
```

Same checks as the TypeScript script, over real HTTP/2 instead of gRPC-Web — `package:grpc`'s `ClientChannel` + `ChannelCredentials.insecure()` (plaintext, matching the server) and a hand-rolled protobuf wire codec (varint/fixed64/length-delimited) driving `ClientMethod`'s serializer seam directly, no `protoc-gen-dart` step. See [`dart-client/README.md`](dart-client/README.md) for the generated package's own API docs, including per-call `CallOptions` and closing the connection (`runtime.shutdown()`).

## Scope

Model CRUD (ticket #171) plus procedures, unary and server-streaming (ticket #208), on the **server** — see `docs/design/protobuf.md` §7.2 for exactly what "server-streaming" means for a `List`-arity procedure (the whole `repeated result` list travels in one streamed message, not itemwise-incremental delivery). None of the three **clients** has a method for the two procedures yet — client-side procedure support for gRPC is out of scope for #208 and not yet ticketed. `list()` on all three clients supports `limit`/`offset`/`fields`/`include`/`sort`; raw predicate queries (`where`/`or`) and structured filters aren't wired up in any generator yet.
