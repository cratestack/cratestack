# MCP operator: security test plan

**Status:** written for cratestack#1041 (ADR 0002 phase 6, the MCP release gate), against `main` at
`3de06144` plus the phase 6 branch. **Source of truth:** ADR 0002 § Security requirements
(`cratestack-docs/internals/mcp-operator-adr.md`, revised 2026-09-24, cratestack-docs#96). Epic:
cratestack#1033.

This maps each of ADR 0002's 13 security requirements to the tests that prove it, by file and test
name. It then does the same for the requirements the phases added. Every cited test was checked to
exist in the tree; `cargo test --list` on each crate lists it. Where no test proves a requirement,
or proves only part of it, the table says so. It does not stretch a nearby test to cover the gap.

Streamable HTTP unless the case name says otherwise.

## Gaps that are not blockers, for the maintainer

- **Requirement 7:** add a test that each tool's schema `$defs` contains only types reachable from
  that tool's arguments and output.
- **Requirement 8, stdio:** a trybuild case that `StdioServer` cannot be built without a context
  would pin the signature against a future convenience constructor.
- **Requirement 12:** response timing for hidden and missing rows is not measured.
- **Requirement 13:** today one principal's REST and MCP calls have separate budgets (different
  keys, see the table). Decide whether that is intended, then pin it either way. Also decide
  whether MCP's key should hash the principal id the way REST's does.
- **The conformance driver itself:** the run's count and distinct-name checks catch a skipped,
  dropped or duplicated case, and a client whose exit status is ignored. They cannot catch a
  weakened predicate, or a `check()` that records every case as passed. Measured: with `check()`
  neutered and the read policy widened, six cases print `FAIL` and the run still exits 0. Only
  review catches a weakened driver.
- **Found during the #1041 conformance run, not security:** `StdioServer` has no
  `with_implementation`, so a stdio server always reports `serverInfo` as `cratestack-mcp`. The HTTP
  builder has it. And an `Int` argument's JSON Schema bounds are `i64::MIN..=i64::MAX`, which a
  JavaScript client parses as `±9223372036854776000`, past the real bounds. A value there fails to
  decode and gets an `isError` result, so it fails safe.
